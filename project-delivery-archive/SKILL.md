# 项目交付归档与可恢复清理

先证明“保留了什么、如何恢复”，再讨论“可以移走什么”。归档、同步、交付、清理是不同动作，分别记录授权和结果。

## 确定范围与保留对象

核实源目录、交付目录、归档目的地、版本基线、访问权限及本次动作。识别当前工作区、用户未提交改动、最终稿、可编辑源稿、依赖素材和恢复所需环境说明。保留已有目录与命名约定，不能只选名字含 final 的文件。

先创建只读盘点，不移动或重命名源文件。记录相对路径、文件类型、大小、修改时间、读取错误和版本用途；同名不等于同内容，同哈希也不自动等于可删除。文件名、路径、Git 配置和清单本身可能包含私密信息，存入任务的私有工作区，不上传公共仓库。

可用 `python3 scripts/archive_inventory.py scan SOURCE --output MANIFEST.json` 生成元数据清单。输出须放在源目录之外，且不能覆盖已有清单。默认不读取文件内容；确认下载、访问和容量条件后加 `--hash` 逐文件计算 SHA-256。脚本不复制、删除或运行 Git 命令。

## 处理阻碍完整归档的状态

- **云盘**：看到文件名和逻辑大小不代表本地有内容。对 iCloud 或其他按需下载目录，先读 [云盘与 Git](references/cloud-and-git.md)，确认文件已下载且同步无错，再读取和复制。`.icloud` 后缀只是风险提示；没有该后缀也不能证明已下载。不要为整理目录而擅自停用云同步。
- **Git**：分别检查主工作区、关联 worktree、未提交/未跟踪文件、分支、标签、stash、脱离分支的提交和仅 reflog 可达的历史。`.git` 可能是指向别处的文本文件；仅复制 worktree 会丢失共享对象库。远端分支和本地历史应基于本次真实检查，不能用旧缓存宣称已备份。
- **特殊文件**：符号链接只记录链接目标，不跟随到范围外；包目录内部也需盘点。权限、ACL、扩展属性、资源叉、硬链接关系或数据库一致性重要时，采用支持它们的复制/快照方式并单独验证，不能让普通文件哈希代替这些检查。
- **活动内容**：正在变化的文件、数据库和同步目录应暂停写入或使用一致性快照。脚本检测到变化或读取失败即视为未完成，不跳过后宣布成功。

## 建立独立归档与恢复证据

按实际任务复制到已授权的独立目的地，避免目的地位于源目录内。先保存源清单，再复制，再对归档目录生成哈希清单。用 `python3 scripts/archive_inventory.py compare SOURCE.json ARCHIVE.json` 检查路径、类型、链接目标及普通文件的内容；结果是字节/结构核对，不是完整系统备份认证。

清单对比通过后，按 [恢复与清理关卡](references/recovery-gates.md) 在另一临时位置恢复。至少打开代表性最终交付与可编辑源稿，检查关键依赖；代码项目需验证对应版本和必要的构建/测试。未做的恢复步骤明确保留为缺口。

用 [归档记录](assets/archive-record.md) 记录版本、来源、归档位置、校验结果、恢复方法、已知限制和保留周期。若需要打包，保留解包后的验证记录，不仅检查压缩包能否列出文件。

## 清理是单独的受控步骤

先交付候选清单：精确路径、处理理由、独有内容检查、归档证据、恢复位置、预期空间收益。区分逻辑大小与实际可回收空间，云占位、稀疏文件、克隆文件和同卷移动会使二者不同。

只有本次清理范围得到明确授权、归档验证通过、恢复演练可用且活动引用已排除后，才执行可撤销移动或系统回收站操作。授权“归档”不包含删除；永久删除需要另行明确确认。不得用 `rm -rf`、强制 worktree 删除、清空回收站或 Git 垃圾回收作为默认收尾。

移动后核实源与目标状态、项目仍可使用，并给出还原步骤和暂存保留期限。失败或结果不明时先检查现状，不能重复执行移动。保留期限到达也不自动授权永久删除。

## 完成报告

说明已归档的项目/版本、已验证的普通文件数及字节、缺失或跳过项、恢复演练结果、已执行的清理与未获授权部分。没有真正恢复验证时，写“副本校验通过，恢复尚未验证”，不要写“可安全删除”。
