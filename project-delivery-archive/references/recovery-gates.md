# 恢复与清理关卡

| 关卡 | 所需证据 | 不通过时 |
| --- | --- | --- |
| 范围确认 | 源路径、目的地、版本、授权动作 | 只读盘点，询问关键缺口 |
| 完整读取 | 所有目标项可读，云占位和异常已解决 | 标为不完整，不允许清理 |
| 复制验证 | 独立副本，逐文件哈希与结构匹配，特殊元数据单验 | 保留源目录，查差异 |
| 恢复验证 | 隔离位置还原，可打开/编辑，必要依赖与历史可用 | 只称副本已创建 |
| 使用排除 | 无运行中的引用、唯一 worktree 历史、未归档版本 | 缩小候选范围 |
| 清理授权 | 精确候选范围、动作、恢复途径已获批准 | 交付候选清单，不执行 |
| 操作核实 | 移动已完成，目标存在，恢复说明有效 | 查现状，不盲目重试 |

## 恢复抽样与全量校验的区别

普通文件应全量内容校验。恢复演练可按风险选择代表性文件，但须说明抽样范围：最终成品、可编辑源文件、引用素材、大文件、非 ASCII/长路径、数据库或工程项目。关键且不可替代的成果应逐项实际打开。

跨平台复制需核对大小写冲突、Unicode 文件名规范、路径长度、可执行位、符号链接、扩展属性与资源叉。脚本只核对相对路径、类型、普通字节、符号链接目标；其结果不能证明上述元数据已保留。

## 清理候选不能只靠重复检测

相同内容可能承担不同路径引用、交付包或版本证据。先检查是否有外部引用、相对链接、自动化流程和客户交付要求，再判断保留哪一份。Git 仓库即使当前文件一致，也可能拥有不同分支、历史、stash、配置或未跟踪内容。

## 停止条件

发现唯一副本、无法下载、哈希变化、恢复失败、权限错误、未授权目标或不确定的移动结果，立即停止受影响项；其他独立盘点可以继续。不得改变保留规则、扩展删除范围或绕过权限来追求“全部清空”。
